# 详细知识卡片与图增强问答设计

## 目标

知识卡片继续以第二层 `TeachingBlock` 为原子单位，但不能只是节点摘要的字段映射。每张卡片需要基于其直接引用的 MinerU 原文、所属一级知识和二级关系生成可独立学习的详细内容。全库问答优先使用卡片，沿知识网补充直接相关卡片，并保留到课件原文范围的追溯能力。

## 数据流

1. 两层知识网和叙事顺序生成基础卡片。
2. 以最多 3 个并发请求深化卡片；每张卡片只加载自己的原文和直接关系。
3. 模型返回摘要、自然 Markdown 正文、关键点、条件、示例、误区和自检问题。
4. 单卡失败时保留基础卡并标记 `partial`，不阻断其他卡片。
5. 保存项目时将详细字段、原文摘要和主题关系写入 IndexedDB 检索记录。
6. 问答先执行字面加权检索，再扩展同一一级知识和一跳关联主题，最后由模型基于候选卡片组织答案。

## 关键决策

- 暂不引入向量数据库或 embedding 模型。项目当前只配置知识生成模型，强行加入 embedding 会增加配置和失败面。
- 卡片深化使用受控并发 3，避免串行等待，同时保留结果顺序。
- 原文摘要和卡片派生正文分开传入问答模型，防止派生内容冒充课件原文。
- 无卡片命中时仍允许通用回答，但必须单独标记且不得生成卡片引用。
- 旧课程通过“重新深化卡片”单独升级，不要求重新运行 MinerU 和知识结构提取。
- 卡片变化会清空旧的综合与完整笔记，因为这些下游产物已经过期。

## 失败与恢复

- 单卡 API、JSON 或超时失败：保留基础卡片并继续。
- 全部卡片失败：任务显示失败，但已有卡片不会丢失。
- 问答页面每次提交前重新读取索引，避免页面常驻期间漏掉新卡片。
- 模型引用会被限制为实际召回的 `cardId`；无有效引用时回退到排名前三的真实卡片。

## 验证

- 卡片深化接入流水线且不会提前生成完整笔记。
- 结构化字段与原文摘要进入检索记录。
- 字面命中可扩展同主题和直接关联主题卡片。
- 问答提示包含原文摘要、检索来源和真实卡片 ID。
- 界面展示详细字段并支持旧课程单独重新深化。
