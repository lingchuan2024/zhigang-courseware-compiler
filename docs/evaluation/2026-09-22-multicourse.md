目标：验证课件经过两层知识结构、知识卡片、课程母笔记之后，是否形成有依据、能独立学习的材料；不能把关联覆盖率或章节生成成功等同于事实正确。

原始测评输出保存在忽略目录 `.uploads/evaluation/multi-{physics,python,writing}-{base,r1,r2}/`。其中 `notes.md` 是实际自动生成结果，不是人工润色稿。`requests.json` 记录提供商返回的 token（含截断和重试），`metrics.json` 记录阶段时间。MinerU 未返回 token 用量，不能算入 DeepSeek token 总量。

## 基准发现

- Python：53 张卡片、4 章全部生成，但两个 Python 代码块无法解析：一个类方法缩进损坏，一个混入了控制台输出。MinerU 对截图的错误识别进入了笔记。
- Python：笔记重复把实例方法称为“类方法”，把 self 约定泛化为强制命名；类本身的对象身份、带默认值的初始化参数也需要更准确的限定。
- 原课件中存在需要解释的简写。修正必须注明依据或教学澄清，不能悄悄伪造成课件原话。

## 第一轮：原始证据与代码缩进

修复母笔记组装时按段落 trim 导致的代码缩进破坏；综合主题时重新提供去重、有预算上限的原始课件摘录，明确区分原始证据与派生卡片，并要求保留条件、分离代码与输出、标记澄清。测评脚本增加按阶段计费统计和跨课件缓存校验。

为了隔离笔记阶段的变化，本轮复用各自基准的解析与知识卡片，未重新生成知识结构。下表仅比较**笔记阶段**，不把缓存后的耗时冒充全流程提速。

## 第二轮：卡片粒度、可定位的代码错误与公式渲染

重新运行三个完整课件的知识结构、卡片与笔记生成，复用各自的 MinerU 解析缓存。移除二级结构提示中“自由组织”与“必须按19类拆分”的矛盾，将同一学习目标下的定义、性质、例子合并；把原始证据约束同时用于卡片深化和笔记综合。

新增保守的 Python 代码排版检查，定位冒号后的缩进、输出混入代码、未匹配括号，并在卡片和章节生成时进行有上限的修复。修复仍失败时保留 partial/failed 状态。此检查不等同于 Python 解释器。额外用 Python AST 检查实际产物，不执行生成代码。

修复引用块内多行公式丢失引用前缀的根因，同时覆盖历史笔记的渲染。基准热学同一份 Markdown 在新渲染器中由6个公式错误变为0，显示公式由63处恢复为69处；这项验证不依赖重新生成更“幸运”的文本。

### 对最初目的的判断：仍需复核，不能当成完整教材

代码与公式的可读性、代码原稿保留、重复卡片数量有实证改善。但“结构生成完成”和“源码块已关联”都不能替代事实验收：

1. **写作的语义错误仍存在。** 第4页箭头指向小写页码缩写 `p.`，自动笔记仍写成作者姓氏不大写，甚至称示例中的 `Jones` 未大写。通用证据提示未解决空间关系丢失，不能声称已经修复。10%建议与APA规范的边界也还不够清晰。
2. **热学存在内容遗漏。** 来源关联覆盖率由95.12%降至92.68%，丢失内容包含氧气瓶质量计算例题的部分来源、正态分布公式等，不能把卡片变少直接算作质量提升。Python关联覆盖率仍88.62%，写作为97.71%。
3. **补上合并阶段的来源保留机制。** 代码审查发现全局合并只校验候选ID、实际忽略候选完整来源；局部合并也只依赖模型重写的来源列表。现统一保留显式引用候选的完整来源，遗漏的候选证据单独保留，不按邻近关系猜测归属。回归测试已验证候选来源不会因合并响应省略而丢失；这是本轮验收后的修复，**未再次重跑全部三份课件，不声称上表遗漏已经在自动笔记中恢复**，也不能恢复候选提取阶段本身遗漏的内容。
4. 写作课件中的作业、扣分、通知仍占据较多独立章节；笔记有“课件未提供……”等编写说明，尚未达到精简、可独立学习的教材叙事质量。热学的主题降级也使章节上下文质量不均。
