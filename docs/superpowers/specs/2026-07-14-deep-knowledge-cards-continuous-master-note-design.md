# 深度知识卡片、连续完整笔记与课件级联删除设计

## 1. 背景与目标

当前实现已经具备 MinerU 解析、两层知识网、知识卡片和课程母笔记的基本链路，但实际使用暴露出三个核心问题：

1. 部分知识卡片只是原文或笔记片段的浅层改写，出现“可能包含”“可以介绍”等空泛内容，无法作为可靠学习材料。
2. 完整笔记页面默认只显示当前章节，左侧目录会替换正文，用户无法通过滚轮从课程概述连续阅读到课程结尾。
3. 课件库缺少删除单份课件和删除整个课程空间的入口，派生数据也没有明确的级联清理规则。

本次改造的目标是：

- 让知识卡片成为事实受控、内容完整、可独立复用的“知识原料包”；
- 让完整笔记成为基于知识卡片重新组织的连续课程讲义，而不是卡片拼接或章节截取；
- 用课程概述、并列知识归纳、完整推导和明确的 AI 教学补充弥补课件讲解不足；
- 为课件库增加可预测、可确认、可验证的两级删除能力。

最终生成链路为：

```text
MinerU Markdown
→ 两层知识网
→ CardContextBundle
→ 深度知识卡片
→ 卡片质量检查
→ 一级知识综合
→ 课程概述与章节规划
→ 章节重写
→ 连续完整笔记
```

## 2. 产品原则

### 2.1 卡片负责知识完整，笔记负责教学组织

知识卡片不是最终课程笔记，也不是完整笔记中的一段截取。它对应一个二级知识节点，负责把该节点讲清楚，并保留原文证据、关系和生成状态。

完整笔记以全部合格卡片为事实材料，按照一级网和二级网的遍历顺序重新组织课程内容。模型可以合并、比较、过渡和重排，但不能把无证据的内容伪装成课件原文。

### 2.2 课件事实与教学补充分层

- MinerU 原文和公式是一级事实来源。
- 知识卡片和完整笔记是基于证据的派生材料。
- AI 可以补充通用教材知识、直觉、典型例子和课件省略的推导步骤。
- 所有无法直接归属于课件证据的补充必须使用统一标记：

```markdown
> AI 教学补充：以下内容用于补足课件省略的解释或推导，不属于课件原文。
```

### 2.3 局部失败不能摧毁整条流水线

卡片、一级综合、章节或索引失败时，保留其他已成功结果。用户可以只重试失败单元，旧的可用版本在新版本成功前不被清空。

## 3. 深度知识卡片

### 3.1 输入上下文

卡片生成不再只输入当前节点的一段原文，而是构建受控上下文：

```ts
interface CardContextBundle {
  courseId: string;
  documentId: string;
  topic: KnowledgeTopic;
  block: TeachingBlock;
  sourceRanges: SourceRange[];
  siblingBlocks: Array<Pick<TeachingBlock, "id" | "title" | "type" | "summary">>;
  oneHopRelations: TeachingRelation[];
  prerequisiteSummaries: string[];
  terminology: Record<string, string>;
  symbols: Record<string, string>;
}
```

输入边界如下：

- 必须包含当前二级节点直接引用的全部原文范围；
- 包含同一一级知识下的二级目录，但不重复塞入所有兄弟节点全文；
- 包含一跳前置、推导、对比、组成等直接关系；
- 只输入必要的术语和符号，避免上下文不断增长；
- 对证据过少的节点明确标记 `sparseEvidence`，允许谨慎教学补充，但不得编造课件结论。

### 3.2 类型自适应生成

二级节点类型保持开放，模型先判断最适合的讲解策略，再生成内容。常用策略包括但不限于：

- 概念类：课程位置、直觉、正式定义、性质、边界、相关概念、误区；
- 公式与推导类：假设、符号、起点、逐步推导、结论、解释、成立条件；
- 方法类：解决的问题、核心思想、步骤、复杂度或代价、适用条件、例子；
- 对比类：比较对象、共同目标、比较维度、对比表、选择建议；
- 分类或知识族类：总览、分类依据、各分支特点、联系、选择地图；
- 案例类：问题设定、使用知识、求解过程、结果解释和可迁移结论。

禁止为所有卡片机械填充相同模板。输出结构可以不同，但必须形成可独立学习的完整内容。

### 3.3 卡片内容结构

沿用现有 `KnowledgeCard`，重点使用并补强以下字段：

```ts
interface KnowledgeCard {
  id: string;
  topicId: string;
  teachingBlockId: string;
  title: string;
  summary: string;
  detailedNote: string;
  keyPoints: string[];
  formulas: FormulaItem[];
  applicableConditions: string[];
  examples: string[];
  misconceptions: string[];
  selfCheckQuestions: string[];
  sourceRanges: SourceRange[];
  prerequisiteIds: string[];
  relatedIds: string[];
  status: GenerationStatus;
  sourceVersion: number;
  cardVersion: number;
}
```

页面中 `detailedNote` 是卡片主体，其他字段按内容实际存在情况渲染。公式必须交给统一 Markdown/KaTeX 渲染器，不能因单个公式解析失败把整段文字显示成红色原始 LaTeX。

### 3.4 卡片质量门

每张卡片生成后先执行确定性检查，再在需要时执行一次模型审查。

确定性检查至少包括：

- 正文不是空字符串，长度达到与节点类型相适应的最低要求；
- 不包含“可能包括”“表格可能包含”“可从以下方面介绍”等占位表达；
- 引用的 `SourceRange` 能在当前课件中解析；
- 推导类包含两个以上明确步骤或说明课件证据不足；
- 对比类至少包含两个对象和两个比较维度；
- 公式中的主要符号有解释或能从全局符号表解析；
- AI 教学补充使用统一标记。

质量检查失败时只重试当前卡片。第二次仍失败则保留失败状态和具体原因，不用空卡片继续生成完整笔记。

## 4. 一级知识综合与完整笔记

### 4.1 一级知识综合

同一一级节点下的合格知识卡片先生成 `TopicSynthesis`：

```ts
interface TopicSynthesis {
  topicId: string;
  framework: string[];
  orderedCardIds: string[];
  parallelGroups: ParallelGroup[];
  comparisons: ComparisonItem[];
  formulaChains: FormulaChain[];
  gaps: TeachingGap[];
  markdown: string;
  status: GenerationStatus;
}
```

该阶段负责：

- 按二级网遍历顺序重排卡片，而不是按生成完成顺序拼接；
- 合并重复定义和重复例子；
- 识别并列概念、方法族、情况分支和适合表格呈现的比较关系；
- 把相关公式整理为“前提—符号—起点—步骤—结论—条件”的推导链；
- 识别课件跳步、解释不足、缺少总览等教学缺口；
- 输出一级知识的内部讲解框架和供章节阶段使用的浓缩材料。

### 4.2 课程概述与章节规划

完整笔记开头必须提供：

- 课程讨论的核心问题；
- 一级知识框架；
- 推荐学习路线及前置关系；
- 主要方法族或概念族的全局地图；
- 课程中最重要的公式链和它们之间的关系。

章节规划根据一级知识网、稳定遍历顺序和 `TopicSynthesis` 生成，不以 PPT 页码直接充当学习顺序。

### 4.3 章节重写

章节生成输入为相关 `TopicSynthesis`、直接前置摘要、章节目标、术语表和符号表。章节不是卡片标题加正文的拼接，而是一次受约束的教学重写。

每章根据内容自然组织，并尽可能完成：

- 开篇说明本章解决什么问题以及与前文的关系；
- 知识较多时先给出章节框架；
- 对并列知识做总览、分类、对比和选择建议；
- 对推导给出假设、符号、完整步骤、结论与适用条件；
- 插入必要的直觉、例子、误区和自检问题；
- 结尾总结本章知识关系，并自然引出后续章节。

### 4.4 连续完整笔记交互

完成状态下，正文区域默认渲染已经组装的整份 `CourseMasterNote.markdown`，而不是默认选中第一章后只显示 `activeChapter.markdown`。

- 用户可以通过鼠标滚轮从课程概述连续阅读到课程总结；
- 左侧目录始终显示课程层级，只负责滚动到正文锚点；
- 当前阅读章节通过 `IntersectionObserver` 自动高亮；
- 点击目录不替换正文，也不重新请求模型；
- 正文使用单一垂直滚动容器，避免页面、目录和正文出现多个互相争抢滚轮的区域；
- 章节失败时在原位置显示局部失败卡片及“重新生成本章”，其他章节仍可阅读。

## 5. 页面布局

### 5.1 深度知识卡片页

- 左栏：按一级知识分组的二级卡片目录，显示遍历编号、状态和缺陷提示；
- 中栏：卡片完整正文，使用教学文档排版，不限制为短卡片高度；
- 右栏：课件原文、来源范围、关系与完整性检查；
- 顶部：重新深化当前卡片、批量生成缺失卡片、进入完整笔记。

### 5.2 连续完整笔记页

- 左栏：固定课程目录和当前阅读位置；
- 中栏：完整课程讲义的单一连续正文；
- 右侧不常驻原文面板，引用点击后以抽屉或浮层显示，避免压缩正文宽度；
- 桌面端正文保持适合长文阅读的最大行宽，窄屏下目录折叠为抽屉。

## 6. 课件库删除

### 6.1 删除单份课件

课件卡片的更多菜单增加“删除课件”。确认弹窗必须说明会同时删除：

- 原始文件记录；
- MinerU 解析 Markdown 和解析状态；
- 两层知识网；
- 知识卡片、一级综合和完整笔记派生内容；
- 该课件对应的检索记录和索引。

删除成功后从所属课程的 `documentIds` 中移除该课件。操作必须幂等，重复请求不能删除其他课件。

### 6.2 删除课程空间

课程空间菜单增加“删除课程”。二次确认后级联删除课程及其全部课件和派生内容。

聊天记录不随课程删除，以便保留用户历史；聊天中已经生成的引用标题和摘要作为历史快照继续显示，但点击已删除来源时明确提示“原课件已删除”。

### 6.3 存储一致性

仓储层提供明确的 `deleteDocumentCascade(documentId)` 和 `deleteCourseCascade(courseId)`，由仓储统一处理数据关联，UI 不直接逐表删除。

若本地存储不支持真正事务，使用“先收集目标 ID—逐项删除—最后更新父对象”的固定顺序，并在任何失败时返回未完成项，允许重试清理。删除结束后重新构建受影响课程的检索索引。

## 7. 模型调用与缓存

- 系统提示词、JSON Schema 和固定质量规则保持稳定，放在请求前部，以提高 DeepSeek 前缀缓存命中率；
- 动态上下文按稳定字段顺序序列化，数组使用稳定遍历顺序；
- 每张卡片以 `sourceVersion + structureVersion + promptVersion` 计算输入指纹，相同输入直接复用已有结果；
- 一级综合以全部依赖卡片版本计算指纹；
- 章节以依赖的 `TopicSynthesis` 版本和章节计划版本计算指纹；
- 并发只用于互不依赖的卡片或章节，设置小规模并发上限并处理限流，不把整份课件一次性交给模型。

## 8. 错误处理

- 模型 JSON 输出先去除代码围栏，再执行结构化解析；
- 首次解析失败时使用一次受限修复，不重新生成全部内容；
- 修复仍失败时记录原始响应摘要、失败阶段和单元 ID；
- 新版本生成成功前保留旧版本，防止“重新深化”后页面变空；
- 完整笔记只消费状态为可用且通过质量门的卡片；
- 缺失内容在课程概述和章节位置显示明确提醒，不能静默省略。

## 9. 验收标准

### 9.1 知识卡片

- 对概念、方法、对比和推导节点分别生成符合类型特征的完整卡片；
- “方法对比表”不能再出现泛化占位内容，必须列出真实比较对象和维度，证据不足时明确说明；
- 推导卡片包含可检查的连续步骤、符号说明和适用条件；
- AI 教学补充与课件证据在视觉和文本上可区分；
- 单卡失败可独立重试，不影响其他卡片。

### 9.2 完整笔记

- 页面初次进入即显示整份笔记，而不是第一章片段；
- 滚轮可以从课程概述连续阅读至课程总结；
- 点击目录滚动到对应标题，正文不被替换；
- 并列知识有归纳或对比，复杂章节先展示框架；
- 公式推导完整，引用和 AI 补充标签正确；
- 单章失败不会使整页不可用。

### 9.3 删除与回归

- 可以分别删除单份课件和整个课程空间；
- 所有派生内容和检索索引按规则清理，其他课程不受影响；
- 历史聊天可继续打开，已删除来源显示失效状态；
- Markdown、表格、代码块、行内公式和块级公式均正确渲染；
- 类型检查、构建、单元测试和关键交互测试通过。

## 10. 非目标

本次不实现多人协作、云端账户同步、卡片自由拖拽编辑或跨用户共享。也不重做 MinerU 服务本身；本次只消费其 Markdown 结果，并改善下游内容组织、生成质量和展示体验。
