# 知纲真实星云工作区背景设计

**日期：** 2026-07-15  
**状态：** 已完成对话确认，等待书面规格审阅  
**范围：** 首页空状态、课件库、全库知识问答、课程加工工作区、笔记与阅读工作区

## 1. 目标

在现有“知识宇宙”主题上，为不同工作空间加入各不相同的真实天文星云背景，同时保证业务主体始终比背景更醒目。

这次改动必须满足以下结果：

1. 不同页面拥有可辨识的真实星云气质，而不是共用一张图片或仅做调色。
2. 真实天文照片只负责环境氛围，不代表课程、知识点或交互状态。
3. 课件卡片、问答消息、输入框、正文和主要按钮始终是第一视觉焦点。
4. 首页没有课件或知识时仍有昏暗星云，但不出现解释“为什么没有星云”的空状态文案。
5. 现有数据驱动课程星云保持不变：知识点越多，亮星越多；真实照片不参与该计算。

## 2. 已选方案与取舍

采用“固定页面映射 + 本地真实天文图片 + 统一背景组件”的方案。

没有采用以下方案：

- **所有页面共用一张星云：** 一致性较强，但无法让课件库、问答和阅读形成不同空间记忆。
- **每次进入随机切图：** 新鲜感较强，但页面身份不稳定，也容易出现裁切和对比度不可控的问题。
- **让真实照片响应知识数据：** 会使照片中的自然恒星与可交互知识星产生语义混淆。

固定映射既能建立稳定的页面身份，也能针对每张图片单独校准裁切、暗度和内容安全区。

## 3. 天文影像映射

| 场景 | 影像 | 视觉作用 | 强度 |
| --- | --- | --- | --- |
| 首页无知识 `dormant` | [马头星云 NIRCam](https://science.nasa.gov/asset/webb/horsehead-nebula-nircam-image/) | 像尚未苏醒的知识宇宙；保留期待感，不伪装已有知识 | 最暗 |
| 课件库 `library` | [蜘蛛星云 NIRCam](https://science.nasa.gov/asset/webb/tarantula-nebula-nircam-image/) | 密集年轻恒星与锈红尘埃形成“宇宙档案馆” | 中等偏暗 |
| 全库问答 `qa` | [蜘蛛星云 MIRI](https://science.nasa.gov/asset/webb/tarantula-nebula-miri-image/) | 紫蓝粉雾场更安静、抽象，适合长对话 | 暗 |
| 上传、解析、结构与卡片 `workspace` | [船底座星云“宇宙悬崖” NIRCam](https://science.nasa.gov/asset/webb/cosmic-cliffs-in-the-carina-nebula-nircam-image/) | 橙金地貌与深蓝星海表达知识生成与结构形成 | 中等偏暗 |
| 笔记与阅读 `reading` | [南环状星云 MIRI](https://science.nasa.gov/asset/webb/southern-ring-nebula-miri-image/) | 中心聚焦、外围退暗，帮助注意力收束到正文 | 最重遮罩 |

图片来自 NASA / ESA / CSA / STScI 官方发布。实现时遵循 [NASA 图像与媒体使用规范](https://www.nasa.gov/nasa-brand-center/images-and-media/)，不暗示 NASA 对产品的认可，并在项目内保存来源、对象名称和官方署名。

## 4. 视觉层级

### 4.1 三层结构

页面按以下顺序叠放：

1. **环境层：** 本地真实星云图片、页面专属裁切、暗角和深色遮罩。
2. **空间层：** 导航、侧栏和内容容器使用深色半透明表面，建立清晰的工作区边界。
3. **任务层：** 卡片、消息、输入框、正文、当前选中项和主要按钮，保持最高对比度与最清晰边缘。

真实星云在桌面端的目标可见度约为 12%–20%。这不是一项全局固定透明度：每个场景用独立遮罩校准，但最终必须达到“先看见内容，再意识到背景”的效果。

### 4.2 主体突出规则

- 主内容表面使用约 78%–92% 不透明度的深色底，并配合轻微背景模糊。
- 背景主要从页面边缘、栏间空隙和顶部留白露出，不穿过大段正文。
- 当前操作、主按钮、引用和选中状态可使用更亮的青蓝色；背景不使用同等级高亮。
- 内容区使用清晰边框和局部阴影，避免图片纹理破坏轮廓。
- 阅读场景使用最重遮罩，正文画布接近实色；星云只在外围可见。
- 移动端进一步降低照片亮度，优先保证文字和触控目标清晰。
- 背景照片保持静态，不使用持续缩放、漂移或视差动画。

### 4.3 语义边界

真实照片中的恒星永远不具备按钮、热点、状态颜色或知识含义。只有现有 Canvas 数据层绘制的课程星云与知识星可以表达知识数据并响应交互。

## 5. 首页行为

### 5.1 没有课件或没有知识

首页进入简洁空状态：

- 保留放大的项目名称“知纲”。
- 显示压暗、降饱和的马头星云。
- 保留一个简洁、明确的添加课件入口。
- 不显示“还没有被点亮的知识星”“上传后生成星云”或任何解释没有星云原因的文案。
- 不显示课程数、知识点数、视野缩放控件或移动提示。
- 不绘制可被误解为知识数据的明亮前景星。

这里的马头星云是沉睡的环境背景，不是空数据插画。

### 5.2 已有课程或知识

- 现有 `KnowledgeNebulaBackground` 继续使用课程与知识摘要生成数据星云。
- 每门课程形成独立聚集区，不绘制课程连线。
- 知识点越多，数据层中的亮星和颗粒密度越高。
- 课程热点、拖拽、滚轮缩放、双指缩放和边缘移动保持可用。
- 真实星云不覆盖数据星云；首页已有知识时以数据层为主体，可只保留极弱的环境底色。

## 6. 组件与页面架构

### 6.1 `AstronomyBackdrop`

新增一个无业务状态的展示组件，建议位置为 `src/components/backgrounds/AstronomyBackdrop.tsx`。

公开接口只表达页面场景：

```ts
type AstronomyBackdropVariant =
  | 'dormant'
  | 'library'
  | 'qa'
  | 'workspace'
  | 'reading';
```

组件职责：

- 选择本地图片资源。
- 应用场景专属 `object-position`、遮罩、暗角和移动端强度。
- 提供图片加载失败时的纯深空渐变兜底。
- 标记为装饰性内容，退出辅助技术的阅读顺序。

组件不读取课程、文档、问答或笔记数据，不决定任何业务交互。

### 6.2 页面接入

- `HomeView`：仅在没有知识时显示 `dormant`；现有数据 Canvas 位于其上方。移除 `KnowledgeNebulaBackground` 内的空状态卡片，并在无知识时隐藏视野控件。
- `AppShell`：接受可选背景场景，由 `LibraryView` 传入 `library`，由全库问答页面传入 `qa`。页头保持高不透明度。
- 课程工作区根容器：根据 `stage` 选择 `workspace` 或 `reading`。`upload`、`document`、`mineru`、`structure`、`cards` 使用 `workspace`；`notes` 使用 `reading`。
- 侧栏与各页面主内容容器：从不透明纯色调整为经校准的深色表面，但不得为了露出背景牺牲可读性。

该边界让后续替换图片或调整遮罩时不需要修改业务页面内部逻辑。

## 7. 资源与性能

- 官方原图只作为来源，产品运行时不请求 NASA 外链。
- 每张图下载后裁切并转换为 WebP；桌面主资源最长边建议约 1920–2560 像素，质量以肉眼无明显色带为准。
- 如果移动端实测资源压力明显，再提供较小 `srcSet`；首版不预先制造多套无用资源。
- 背景组件使用 `<picture>` / `<img>` 而非 CSS 远程 URL，以便处理加载状态和解码。
- 非首屏工作区图片可延迟加载；当前页面背景不能阻塞业务内容渲染。
- 图片加载失败时展示与该场景色相接近的深空渐变，布局和文字保持不变。
- 项目内新增影像署名文件，记录官方页面、对象名称、发布机构和使用位置。

## 8. 无障碍与适配

- 装饰图片使用空 `alt` 并设置 `aria-hidden="true"`，不制造无意义的朗读内容。
- 背景不接收指针事件，也不进入键盘焦点顺序。
- 文字、按钮和状态不能只依赖照片颜色区分。
- 关键正文与操作目标维持足够的局部对比度；若图片裁切变化导致冲突，优先加重遮罩而不是移动业务主体。
- `prefers-reduced-motion` 下没有额外处理成本，因为照片背景本身不运动；现有数据星云仍遵守其减弱动画逻辑。

## 9. 测试策略

### 9.1 组件测试

- 每个 `variant` 选择正确的本地资源、场景类名和装饰性属性。
- 图片错误事件触发渐变兜底，不移除子内容。
- `AppShell` 能接入可选背景且保持原有导航和 action 行为。

### 9.2 首页测试

- `summaries=[]` 或所有 `knowledgeCount=0` 时显示 `dormant` 背景。
- 空首页不包含“还没有被点亮的知识星”等解释文案。
- 空首页不显示缩放控件和课程热点，只保留品牌与添加课件入口。
- 有知识时维持课程热点与数据星绘制；亮星数量仍由知识摘要决定。

### 9.3 页面集成测试

- 课件库、全库问答、加工工作区和笔记工作区映射到各自背景。
- 删除课程、发送问答、打开引用、切换工作阶段等现有业务行为不回归。
- 窄屏下侧栏、消息时间线、输入框和内容卡片不因背景层产生新的溢出或点击遮挡。

### 9.4 验证命令

实施完成后运行相关组件测试、全量测试、类型检查和生产构建。全局 lint 结果需要区分项目源码与现存未跟踪第三方评估文件；本次改动的源码必须通过定向 lint。

## 10. 完成标准

以下条件全部满足才视为完成：

1. 五个场景使用五种明确不同的真实天文影像气质。
2. 页面主体在第一眼明显强于背景，长时间阅读和问答不受干扰。
3. 空首页简洁且没有解释“没有课件所以没有星云”的话术。
4. 无知识时有昏暗星云，有知识时数据驱动亮星仍随知识量增加。
5. 真实照片中的星与可交互知识星不存在交互或视觉语义混淆。
6. 图片本地化、压缩、可降级，并保留完整官方来源与署名。
7. 现有课件库、问答和课程处理流程通过回归验证。
