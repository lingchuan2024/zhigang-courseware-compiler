# 星空知识宇宙与全站深色主题设计

## 1. 目标

本次改造把首页从静态产品介绍页升级为由真实课程知识生成的“知识宇宙”，并将整个项目统一为深空观测站风格。

用户已经确认以下决策：

- 全站采用深色星空主题，不保留浅色主界面；
- 知识卡片生成完成即视为该知识点已点亮；
- 一级知识点作为主星，二级知识点作为伴星，知识关系作为星轨；
- 视觉方向采用“深空观测站”：蓝黑背景、青色知识星、金色核心节点和克制动画；
- PDF/PPT 原始页面保持原色，避免课件内容被强制反色。

首页需要让用户在进入项目时直接理解：自己拥有几个课程星系、已经点亮哪些知识、知识之间如何连接，以及接下来可以继续处理什么。

## 2. 视觉原则

### 2.1 深空观测站

主界面以蓝黑深空为底，知识内容承担主要亮度。星空是信息结构，不是随机装饰。

- 主背景不使用纯黑，而使用带少量蓝色的深空色；
- 普通知识使用青色，当前选中知识使用蓝色光环；
- 核心、高重要度知识使用克制的金色星核；
- 错误使用暗红边缘，不使用强烈闪烁；
- 大面积正文和表格放在稳定的深蓝灰面板中；
- 动态星空仅用于首页和知识网络，阅读页面使用静态深色背景。

### 2.2 全局色板

```css
:root {
  --space-950: #050914;
  --space-900: #081222;
  --space-850: #0a1628;
  --space-800: #0d1a2c;
  --space-750: #12233a;
  --space-border: #20344d;
  --space-border-strong: #315170;

  --star-primary: #73e5d7;
  --star-secondary: #69a9ff;
  --star-core: #f1c976;
  --star-dim: #50647d;
  --star-danger: #ff746c;

  --text-primary: #edf7ff;
  --text-secondary: #b6c8da;
  --text-muted: #8fa4bf;
}
```

组件不得继续散落硬编码米白、墨绿和朱红色。Tailwind 中保留兼容别名，但新组件优先使用语义变量。

### 2.3 字体与层次

- 标题继续使用中文衬线字体，保持“知纲”的学术气质；
- 正文使用 `Noto Sans SC`、`PingFang SC` 等清晰中文无衬线字体，不再把 Inter 作为首选；
- 数据、节点编号和状态使用 JetBrains Mono 或系统等宽字体；
- 正文不使用发光文字，发光只属于节点、连线和少量关键状态。

## 3. 首页信息架构

首页主要分为四个区域：

```text
顶部导航
├── 品牌
├── 课件库
├── 全库问答
└── 服务配置

主视觉
├── 左侧产品说明与主要操作
└── 中央/右侧真实知识星图

知识统计
├── 课程星系数
├── 已收录课件数
├── 已点亮知识数
└── 核心知识数

继续学习
├── 最近更新课程
├── 处理中课件
└── 失败或待继续任务
```

首页不再保留当前三张静态功能介绍卡作为主要内容。产品能力通过真实知识星图、统计和继续学习入口表达。

## 4. 星空数据模型

### 4.1 映射规则

```text
课程空间       → 星系
一级知识点     → 主星
二级知识点     → 伴星
一级知识关系   → 主星轨道
二级知识关系   → 子星轨道
知识卡片完成   → 星点亮起
待生成         → 暗星
生成失败       → 暗红边缘星
```

“已学习”在本版本中的产品定义是：对应二级知识节点已经成功生成知识卡片。它不表示用户已经通过测试或真正掌握。界面统一使用“已点亮”而不是“已掌握”，避免产生错误承诺。

### 4.2 轻量摘要

首页不能读取每张卡片的完整 Markdown。新增独立的星图摘要：

```ts
interface KnowledgeSkySummary {
  courseId: string;
  documentId: string;
  courseName: string;
  documentTitle: string;
  topics: SkyTopic[];
  topicRelations: SkyRelation[];
  learnedCardCount: number;
  totalBlockCount: number;
  coreTopicCount: number;
  updatedAt: number;
}

interface SkyTopic {
  id: string;
  name: string;
  importance: KnowledgeTopic['importance'];
  status: KnowledgeTopic['status'];
  cardCount: number;
  completedCardCount: number;
  companionStars: SkyKnowledgeNode[];
}

interface SkyKnowledgeNode {
  id: string;
  teachingBlockId: string;
  cardId?: string;
  title: string;
  type: string;
  status: GenerationStatus;
}

interface SkyRelation {
  id: string;
  sourceId: string;
  targetId: string;
  type: string;
}
```

课件快照保存、知识结构更新或知识卡片更新时，同时重新计算对应 `KnowledgeSkySummary`。课件删除和课程删除必须级联删除这些摘要。

### 4.3 兼容旧数据

旧课件没有星图摘要时，首页在后台根据已有课件快照惰性生成一次摘要并保存。生成失败只忽略当前课件，不影响其他课程展示。

## 5. 星图布局与交互

### 5.1 布局

- 每个课程空间形成独立星系区域；
- 一级主星使用稳定的径向/力导向布局；
- 同一一级知识的二级节点围绕主星排列；
- 相同数据每次进入首页保持相近位置，使用课程 ID 和知识 ID 生成确定性随机种子；
- 首页默认显示所有一级主星，每颗主星最多显示 6～8 个代表性伴星；
- 更多二级节点聚合为 `+N` 星团；
- 点击主星后，当前子星系在原位置完整展开，其他星系降低亮度。

代表性伴星优先级：

```text
已完成核心卡片
> 与其他节点存在多条关系的卡片
> 必修节点
> 原始二级遍历顺序
```

### 5.2 视觉编码

- 主星大小由重要度、伴星数量和关系度数共同决定；
- 已完成卡片对应的伴星使用青色实心光点；
- 待生成伴星使用低亮度空心点；
- 核心一级知识使用金色星核和青色外环；
- 当前选中知识使用蓝色脉冲光环；
- 硬前置关系使用较清晰实线，教学建议使用低透明虚线；
- 星轨仅在悬停、选中或较高缩放级别显示关系标签。

### 5.3 交互

- 点击课程星系标题：进入对应课程空间；
- 点击一级主星：展开或收起该二级知识子星系；
- 点击二级伴星：打开对应课件，并定位到知识卡片页的指定卡片；
- 悬停节点：显示知识名称、所属课程、来源课件、卡片状态和直接关系；
- 键盘 Tab：能够依次聚焦课程、主星和当前展开的伴星；
- Enter/Space：执行与鼠标点击相同的行为；
- Escape：收起当前子星系或关闭详情浮层。

为支持直接进入指定卡片，课程库状态层增加明确入口：

```ts
openDocumentAtCard(documentId: string, cardId: string): Promise<void>
```

该入口加载课件快照、切换到知识卡片阶段，并选中目标卡片。

## 6. 渲染架构

首页星空分成两个互不依赖的渲染层：

```text
StellarBackground
└── Canvas 装饰微星、轻微视差和背景渐变

KnowledgeUniverse
├── SVG 真实节点
├── SVG 知识关系
├── DOM/SVG 可访问标签
└── DOM Tooltip 与操作按钮
```

装饰微星没有点击事件，不进入可访问树。真实知识节点使用 SVG 或 DOM 元素，必须有可读名称和键盘操作能力。

组件边界：

```text
HomeView
├── StellarBackground
├── UniverseHero
├── KnowledgeUniverse
│   ├── CourseGalaxy
│   ├── KnowledgeStar
│   ├── ConstellationEdges
│   └── KnowledgeStarTooltip
├── UniverseStats
└── RecentCourseSystems
```

布局计算放在纯函数模块中，不在 React 渲染期间随机生成坐标。

## 7. 全站主题迁移

### 7.1 基础组件

第一步迁移：

- `AppShell`；
- 页面背景和顶部导航；
- 主按钮、次按钮、危险按钮；
- 输入框、弹窗、标签和状态提示；
- 滚动条、焦点环和加载状态。

### 7.2 页面映射

- 首页：完整动态知识宇宙；
- 课程库：课程作为星系目录，课件作为观测档案卡；
- 课件预览：深空工具栏与外围工作区，PDF/PPT 页面保持白色原貌；
- MinerU 解析：深蓝编辑器和 Markdown 预览；
- 知识结构：主星、伴星、星轨和深空信息面板；
- 知识卡片：深蓝知识档案，正文区域不持续发光；
- 完整笔记：静态深蓝阅读背景、低对比边框和高对比正文；
- 全库问答：深空通讯台，知识卡片引用作为可点击坐标；
- 设置弹窗：保持深色主题，不暴露或显示完整 API Key。

### 7.3 Markdown 与公式

- 标题使用浅色高对比文字；
- 正文使用 `--text-secondary`；
- 表格表头使用 `--space-750`；
- 行内代码和公式使用稳定深蓝灰底；
- KaTeX 文字颜色跟随正文，不添加发光；
- 引用和 AI 教学补充使用青蓝边框；
- 错误公式只在局部显示暗红提示。

## 8. 性能与降级

- 首页最多同时渲染约 200 个真实可交互节点；
- 每颗主星默认只渲染最多 8 个伴星；
- 超出上限的内容通过星团聚合；
- 背景 Canvas 使用设备像素比上限，避免高分屏过度绘制；
- 页面不可见时暂停背景动画；
- `prefers-reduced-motion` 下关闭视差、闪烁和缓动，只显示静态星图；
- 移动端默认只展示课程星系与一级主星，点击后进入简化列表式二级星图；
- 星图摘要损坏时展示其他课程，并提供重新生成摘要入口。

## 9. 空状态与错误状态

### 没有课程

展示少量暗星和“导入第一份课件，点亮你的知识宇宙”按钮，不伪造知识名称。

### 有课件但没有知识结构

显示未成形星云和课件名称，状态为“等待提取知识结构”。

### 知识卡片部分失败

一级主星仍显示；失败伴星使用暗红边缘，并提供进入课件重新生成的入口。

### 摘要读取失败

忽略失败课件，记录错误但不阻断首页。统计数字只计算成功加载的数据，并明确显示“部分数据未加载”。

## 10. 分阶段实施

### 第一阶段：主题基础与首页

1. 建立全局语义色与基础组件主题；
2. 增加 `KnowledgeSkySummary` 生成和存储；
3. 实现装饰星空、真实知识星图和首页统计；
4. 增加星图到课程/卡片的导航；
5. 改造课程库和通用弹窗。

### 第二阶段：工作流页面统一

1. 课件预览与 MinerU 解析；
2. 两层知识网络；
3. 知识卡片；
4. 连续完整笔记；
5. 全库问答和服务配置。

两个阶段都必须保持功能可用，不能在阶段中间出现浅色和深色组件文字对比失效。

## 11. 测试与验收

### 数据测试

- 星图摘要正确映射课程、一级知识、二级节点和卡片状态；
- 已完成卡片准确计入已点亮知识数；
- 删除课件和课程时摘要被级联删除；
- 旧快照可以惰性生成摘要；
- 超量节点按规则聚合且结果稳定。

### 交互测试

- 点击课程进入正确课程空间；
- 点击主星展开对应二级子星系；
- 点击伴星打开正确课件和知识卡片；
- 键盘可以完成相同操作；
- 空状态、失败状态和部分数据状态正确显示。

### 视觉与可访问性

- 主文字和背景达到可读对比度；
- 焦点环清晰；
- 减少动态效果设置生效；
- PDF/PPT 原始页面颜色不被改变；
- Markdown、表格、代码块和 KaTeX 在深色背景下清晰；
- 200 个可视节点下拖动、悬停和展开保持流畅。

### 完成标准

- 首页所有业务星点来自真实项目数据；
- 用户能够直观看到课程星系、一级知识和已点亮二级知识；
- 全站不存在明显遗留的米白主面板或浅色文字冲突；
- 课件、知识网络、卡片、笔记和问答功能保持原有行为；
- 类型检查、生产构建和项目测试通过。

## 12. 非目标

本次不实现知识掌握度测试、学习时长统计、账号云同步、多人共享星图或复杂 3D/WebGL 宇宙。首版使用 Canvas 与 SVG，优先保证信息可读、交互可靠和低性能设备可用。
