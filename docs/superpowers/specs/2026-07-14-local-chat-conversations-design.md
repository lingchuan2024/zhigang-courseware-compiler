# 全库问答本地会话系统设计

## 目标

把当前只能保留一次提问和回答的“全库知识问答”升级为类似 ChatGPT 的本地多会话系统。用户可以新建、切换、重命名和删除聊天；刷新页面后仍能恢复历史；连续追问能够理解同一聊天的最近上下文。每次回答仍以知识卡片检索为核心，并保存可点击、可追溯的卡片索引。

## 已确认的产品决策

- 新聊天默认检索全部课件。
- 同一聊天支持多轮上下文理解。
- 会话和消息保存在浏览器 IndexedDB，不使用容量有限的 localStorage 保存长聊天。
- 界面采用 ChatGPT 式专注布局：左侧聊天历史、中央对话；知识卡片详情按需从右侧打开。
- 第一版不做逐字流式输出，保留明确的检索与生成等待状态。
- 找不到知识卡片时允许模型直接回答，但必须标记为“AI 通用回答”。

## 范围

### 本次实现

- 本地创建和持久化多个聊天。
- 自动恢复最近打开的聊天。
- 会话自动标题、手动重命名和删除。
- 多轮消息保存和展示。
- 基于最近上下文的知识卡片检索。
- 模型回答携带有限长度的最近对话上下文。
- 回答保存来源类型和知识卡片引用快照。
- 点击引用打开右侧卡片详情抽屉并可进入对应课件。
- 请求失败和页面中断后的可恢复状态。

### 不在本次范围

- 用户账号、云端同步和跨设备聊天。
- 分享聊天、导入导出聊天。
- 多人协作。
- 对话分支。
- 逐字流式输出和中途停止生成。
- 长对话自动生成永久摘要；第一版仅使用有界上下文窗口。

## 信息架构与界面

### 左侧会话栏

- 顶部固定“新建聊天”按钮。
- 会话按更新时间分为“今天”“昨天”“更早”。
- 每项显示会话标题并提供重命名和删除操作。
- 当前会话使用明确的选中状态。
- 新建聊天只进入空白草稿界面；用户发送第一条消息后才创建持久化记录，避免产生空会话。
- 删除当前会话后切换到剩余会话中更新时间最近的一项；没有剩余会话时进入新聊天欢迎页。

### 中央对话区

- 顶部显示会话标题和检索范围，默认范围为“全部课件”。
- 用户消息使用右侧气泡。
- AI 消息使用统一 Markdown 和 KaTeX 渲染。
- AI 消息中的“基于知识卡片”与“AI 通用回答”分节显示。
- 回答下方显示知识卡片引用按钮。
- 输入框支持 `Enter` 发送、`Shift+Enter` 换行。
- 请求期间显示“正在检索知识卡片并组织回答”。
- 失败消息显示错误和“重新生成”操作，已提交的用户问题不会丢失。

### 右侧知识卡片抽屉

- 默认关闭，不挤占中央对话宽度。
- 点击回答中的卡片引用后打开。
- 展示课程名、课件名、卡片标题、卡片正文和课件原文摘要。
- 提供“打开对应课件”操作。
- 如果实时索引中的卡片已被删除或重新生成，优先展示消息中保存的引用快照，并标记“卡片已更新或不可用”。

## 数据模型

### ChatConversation

```typescript
interface ChatConversation {
  id: string;
  title: string;
  courseIds: string[]; // 空数组代表全部课件
  createdAt: number;
  updatedAt: number;
  lastOpenedAt: number;
}
```

第一次成功提交问题时，以问题清理后的前约 24 个字符生成标题；标题为空时使用“新聊天”。用户重命名后不再自动覆盖。

### ChatMessage

```typescript
type ChatMessageRole = 'user' | 'assistant';
type ChatMessageStatus = 'pending' | 'completed' | 'failed' | 'interrupted';

interface ChatMessage {
  id: string;
  conversationId: string;
  role: ChatMessageRole;
  content: string;
  status: ChatMessageStatus;
  answer?: RagAnswer;
  citations?: ChatCitationSnapshot[];
  error?: string;
  retryOfMessageId?: string;
  createdAt: number;
  updatedAt: number;
}
```

用户消息的 `content` 保存原始问题。AI 消息的 `answer` 保存分节回答，`content` 保存便于列表或降级显示的合并正文。失败或中断的 AI 占位消息保留对应错误。

### ChatCitationSnapshot

```typescript
interface ChatCitationSnapshot {
  cardId: string;
  courseId: string;
  documentId: string;
  courseName: string;
  documentTitle: string;
  title: string;
  content: string;
  sourceExcerpt?: string;
}
```

引用保存生成当时的必要快照，使历史回答不会因知识卡片重新生成而失去可读性。点击引用时仍优先查找最新 `RetrievalRecord`，最新记录不存在时使用快照展示。

## 本地持久化

在现有 `zhigang-library` IndexedDB 中新增：

- `qa-conversations`：键为 `conversation.id`，建立 `updatedAt` 索引。
- `qa-messages`：键为 `message.id`，建立 `conversationId` 和 `[conversationId, createdAt]` 索引。

数据库版本从 1 升级到 2。升级逻辑只新增对象存储，不删除或重写现有的 `courses`、`documents`、`snapshots` 和 `retrieval-records`。

当前会话 ID 使用一个很小的 localStorage 键保存，仅用于刷新恢复；聊天正文始终保存在 IndexedDB。

## 状态边界

新增独立的 `useQaStore`，避免把聊天生命周期塞入课程工作区状态：

- 加载会话列表和当前会话消息。
- 创建草稿聊天并在第一次发送时持久化。
- 切换、重命名和删除聊天。
- 发送消息、重试失败回答和恢复被中断的消息。
- 管理当前卡片抽屉。

课程库仍由 `useLibraryStore` 管理，课件处理工作区仍由 `useStore` 管理。问答状态只通过公开的课程库与检索仓库函数读取课程、课件和卡片索引。

## 多轮 RAG 数据流

1. 用户发送问题。
2. 如果当前是空白草稿，创建会话并生成本地自动标题。
3. 立即保存用户消息和一个 `pending` AI 消息占位。
4. 读取最新 `RetrievalRecord`，避免问答页常驻时遗漏刚生成的知识卡片。
5. 用当前问题和最近的用户问题构造检索文本。检索文本主要保留当前问题，并补充最近两条用户问题以解决代词和省略主语。
6. 按会话 `courseIds` 过滤卡片；空数组代表全部课件。
7. 读取当前会话最近消息，按最新优先截取，在字符上限内还原为有序上下文。
8. 将最近上下文、当前问题和召回卡片交给回答模型。
9. 保存 `RagAnswer`、引用快照和完成状态，更新会话 `updatedAt`。
10. 如果没有卡片命中，走通用回答分支并保存 `general` 来源，不生成伪造引用。

模型提示必须区分三类输入：历史对话、当前问题、知识卡片正文。历史 AI 回答只能提供对话连续性，不能提升为新的课程事实来源。

## 上下文窗口

- 本地保存全部消息。
- 模型调用不无限发送全部历史。
- 从当前问题之前的消息向前截取，最多包含最近 12 条消息，并受总字符上限约束。
- 检索查询仅补充最近两条用户问题，不直接拼接长 AI 回答。
- 当前问题始终完整保留，不因上下文裁剪而截断。

## 并发与错误处理

- 每个请求绑定固定 `conversationId` 和 AI 占位消息 ID，切换聊天不会改变写入目标。
- 同一会话同一时刻只允许一个生成请求；不同会话可以各自存在独立状态，但第一版界面不主动发起并行批量请求。
- 应用启动时，将数据库中遗留的 `pending` AI 消息转换为 `interrupted`。
- 失败时保存错误文本，不删除用户消息或已有历史。
- “重新生成”复用失败 AI 消息之前最近的一条用户消息，创建新的 AI 占位，并通过 `retryOfMessageId` 记录关联。
- IndexedDB 打开或升级失败时显示“本地聊天存储不可用”，不影响课程库首页和课件工作区继续使用。
- 无模型配置时先打开设置窗口，不创建用户消息，避免留下无法回答的记录。

## 测试策略

### 仓库测试

- 创建、读取、排序、重命名和删除会话。
- 按会话读取有序消息。
- 删除会话级联删除消息。
- 数据库升级后原课程、课件和检索记录仍存在。
- 启动时将遗留 `pending` 消息标记为 `interrupted`。

### RAG 测试

- 当前问题与最近用户问题形成上下文检索文本。
- 最近对话按消息数和字符数裁剪。
- 历史 AI 回答不会被当作卡片事实。
- 卡片回答保存引用快照。
- 无命中时生成通用回答且不包含卡片引用。

### 状态与组件测试

- 第一次发送才创建会话并自动生成标题。
- 新建、切换、重命名和删除聊天。
- 切换聊天后异步回答写回原会话。
- 刷新恢复上次会话。
- 失败消息可以重新生成。
- 点击引用打开抽屉并显示快照，关闭后恢复专注布局。
- `Enter` 发送、`Shift+Enter` 换行。

## 验收标准

1. 用户可以创建至少两个聊天并在它们之间切换，消息互不混淆。
2. 刷新页面后聊天列表和全部消息仍在。
3. 第二轮省略主语的追问能携带前文进入检索和回答提示。
4. 每条卡片回答能打开当时的知识卡片引用详情。
5. 删除、重新生成知识卡片后，旧聊天中的引用仍有可读快照。
6. 无卡片命中时仍能回答，并标记为“AI 通用回答”。
7. 请求失败或页面关闭不会丢失已发送的问题，用户可以重新生成。
8. 原课程库、课件快照和检索索引不受数据库升级影响。
