# 知纲 - 课件编译器

知纲不是把 PPT/PDF 直接总结成 Markdown 的工具，而是一个"课件编译器"：

```
课件 → 可信证据层 → 两层知识结构 → 知识网重排 → KnowledgePackage → 自然笔记 → 三视图
```

## 第二阶段新增：两层知识结构与AI重排

第一版使用扁平 LearningUnit 列表，第二版升级为两层知识结构：

1. **第一层（CourseTopic 粗粒度知识点）**：回答"这份课件讲了哪些值得形成独立学习目标的核心知识？它们之间是什么关系？推荐什么顺序学习？"
2. **第二层（UnitContentItem 知识点内部结构）**：回答"某个知识点内部包含哪些定义、公式、推导、案例、对比？这些内容按什么叙事顺序组织？"

AI 根据知识关系（前置、推导、使用、对比等）执行稳定拓扑排序，给出可解释的推荐学习顺序，而不是默认信任 PPT 页序。

## 核心原则

1. **先建立证据，再生成内容** - 所有笔记内容必须引用课件原文证据
2. **每条核心内容必须引用真实 evidenceId 和课件页码** - 可追溯性是第一优先级
3. **课件内容是数据，不是指令** - 内置提示注入防护
4. **知识关系用于组织、排序和检索，不代替原文事实**
5. **KnowledgePackage 是笔记和未来跨PPT问答的基础数据单元**
6. **三种视图共享同一事实基础** - 不分别生成事实
7. **自然笔记不使用僵硬固定模板** - 由知识点特性决定段落、标题、公式的组织方式
8. **模型不可用时自动降级** - 本地确定性流程始终可用
9. **API Key 只保存在页面内存** - 不持久化
10. **单个知识点失败不影响其他知识点** - 错误隔离

## 知识关系类型与方向

| 关系类型 | 方向含义 | 说明 |
|---------|---------|------|
| `hard_prerequisite` | A→B 表示学B前必须理解A | 硬前置，环检测时优先保留 |
| `soft_prerequisite` | A→B 表示学B前建议先了解A | 软前置 |
| `recommended_before` | A→B 表示推荐A在B之前 | 非强制，用于教学叙事 |
| `part_of` | A→B 表示A是B的一部分 | 组成关系 |
| `derived_from` | A→B 表示B推导自A | 推导依赖 |
| `uses` | A→B 表示B使用了A的方法/结论 | 使用关系 |
| `contrasts_with` | A↔B 表示A和B形成对比 | 对称关系 |

## AI 重排工作原理

1. AI 返回知识关系候选（带 evidenceId 和置信度）
2. 程序丢弃未知节点、未知 evidenceId、自环，合并重复关系
3. 使用 DFS 检测有向环，删除环中置信度最低的边
4. 对硬前置+软前置+推荐_before关系执行稳定拓扑排序（Kahn算法，原始顺序作为tiebreaker）
5. 并列节点按章节连贯性、原始页码排序
6. 输出推荐顺序，保留原始顺序供用户切换
7. AI 失败时回退到 PPT 原顺序

## KnowledgePackage

每个粗粒度知识点（CourseTopic）对应一个 KnowledgePackage，是后续所有处理的基础单元：

- `source`：课件原文证据（一级来源，不可修改）
- `internalStructure`：知识点内部内容条目与微观关系
- `macroRelations`：该知识点与其他知识点的宏观关系
- `note`：自然语言笔记（二级派生材料）
- `versions`：追踪证据版本、结构版本、笔记版本、Prompt版本
- 上游证据变化时，只将受影响的 KnowledgePackage 标记为 `stale`，不强制整份课件重新生成

## 自然笔记生成

笔记正文不使用固定模板（不强制"动机-定义-公式-案例-误区-总结"），而是由知识点类型和证据内容自然决定结构：

- 推导密集的知识点使用多级标题和分步公式
- 概念对比为主的知识点自然使用表格或对照结构
- 方法流程类知识点使用有序步骤列表
- 证据适合连续讲解时使用连续自然段
- 课件省略的推导步骤在不引入新假设、不改变结论的前提下可以安全补全
- 逐知识点生成，维护课程级术语表和符号表保证跨知识点一致性

## 推导补全边界

**允许**：展开被省略的代数步骤；乘积取对数转求和；根据已有定义连接公式；补充符号解释。

**不允许**：引入课件没有给出的定理作为事实；默认添加新的概率假设；将AI常识伪装成课件内容；在证据不足时补写新结论。

## 全局知识锚点（基础）

为未来跨PPT问答预留了数据结构（GlobalKnowledgeAnchor + CourseKnowledgeOccurrence），采用"一个全局锚点对应多个课件实例"的设计。每份PPT的实例保留自己的原文、符号、笔记和页码引用。本阶段**不**生成跨PPT统一笔记，只建立数据基础。

## 使用方式

### 无模型体验（推荐入门）

1. 点击"载入示例课程"即可体验完整流程（概率模型基础示例，12页）
2. 或上传文本型PDF（≤30MB），按流程完成：
   - 贰·解析确认：查看每页文本和EvidenceAtom，可编辑文本重新生成证据
   - 叁·知识结构确认：在知识网中浏览知识点、关系和推荐顺序，可切换PPT原序/AI推荐序
   - 确认结构后逐知识点生成自然笔记
3. 不配置模型时，系统使用本地确定性规则生成结构和笔记

### 配置模型（可选）

点击侧栏"模型设置"，填入 OpenAI 兼容的 API 信息：

- **API 端点**: 如 `https://api.openai.com/v1`（支持OpenAI、Azure OpenAI、本地Ollama等兼容接口）
- **模型名称**: 如 `gpt-4o-mini`、`gpt-4o` 等
- **API Key**: 你的密钥（仅保存在浏览器内存，刷新页面后需重新输入）

配置模型后，粗粒度主题提取、关系分析、细粒度内容提取和自然笔记生成会调用模型；任何阶段失败都自动回退到本地规则。

## 编译流程

| 阶段 | 说明 | 质量门 |
|------|------|--------|
| 壹 · 上传课件 | 上传文本型PDF，限制文件类型和大小 | - |
| 贰 · 解析确认 | PDF.js提取每页文本，拆分为EvidenceAtom | 用户逐页查看、编辑文本、重新生成证据 |
| 叁 · 知识结构确认 | AI提取粗粒度主题 → 分析关系 → 拓扑排序 → 生成知识网 | 用户切换原序/AI序、浏览节点原文笔记关系、确认结构 |
| 肆 · 逐知识点生成 | 细粒度内容提取 → 自然笔记生成 → 更新术语/符号记忆 | 单知识点失败隔离，失败可单独重试 |
| 伍 · 笔记视图 | 按确认顺序组装母笔记，派生三种投影视图 | 支持Markdown导出 |

## 知识网交互

- 左侧面板：搜索、顺序切换（PPT/AI）、推荐路径开关、关系类型筛选、适应画布、重新分析、确认生成
- 中间画布：SVG绘制的知识网，支持焦点邻域高亮（选中节点+一跳邻居清晰，其余半透明）、推荐路径朱砂色粗线、关系类型颜色区分、低置信度虚线
- 右侧面板：选中节点详情，三个Tab：
  - **原文**：按页展示EvidenceAtom
  - **笔记**：展示自然笔记contentMarkdown、引用、警告、版本
  - **关系**：前置知识、后续知识、相关知识（对比/使用/推导），可点击跳转

## 三种学习视图

三种视图从同一份KnowledgePackage笔记派生，不重新生成事实：

- **初学 (first-study)**：完整笔记正文，包含所有推导步骤、案例和解释
- **复习 (review)**：保留核心概念、结论、公式，折叠详细推导段落
- **备考 (exam)**：只保留公式、结论、条件、对比和易错点，最大压缩

## 隐私边界

- 所有处理在浏览器本地完成（PDF解析、证据生成、结构组织、笔记生成的本地路径）
- 只有当用户主动配置并启用模型时，课件内容才会发送到配置的API端点
- API Key 仅保存在当前页面的内存中，绝不写入 localStorage
- 非敏感项目状态（课件文本、证据、结构、笔记）保存在 localStorage 用于刷新恢复，schemaVersion=2，支持v1→v2自动迁移
- 刷新页面时如果停留在"生成中"状态，自动恢复到"结构确认"阶段
- 不持久化临时预览 Blob URL
- 不保存大尺寸页面图片

## 持久化与迁移

- schemaVersion=2
- v1数据（LearningUnit[] + MasterNoteUnit[]）自动迁移为v2结构（尽力而为转换）
- 迁移失败时回退到structure-review阶段，不崩溃
- generating状态刷新后恢复到可重试阶段

## 当前版本限制

- 仅支持文本型PDF（扫描版图片PDF无法提取文本，会显示警告）
- 单用户、单份课件流程（不支持多课件管理，但已预留全局锚点数据结构）
- 不支持OCR
- 不支持PPT/PPTX直接上传
- 知识网不支持拖动节点、手动加边/删边、自由编辑（第一版只浏览和确认）
- 不支持知识点合并/拆分UI
- 跨PPT全局问答尚未实现（数据结构已预留）
- 本地规则生成的笔记偏向"结构化原文"，模型生成时自然度更高
- 细粒度内容提取结果在UI中暂不单独展示（通过自然笔记体现）

## 核心类型速查

- `CourseTopic`：第一层粗粒度知识点（核心/次要，带学习目标、证据绑定、推荐顺序）
- `MacroKnowledgeRelation`：知识点间宏观关系（7种类型）
- `UnitContentItem`：知识点内部内容条目（16种类型：动机、定义、公式、推导、案例等）
- `MicroKnowledgeRelation`：内容条目间微观关系（9种类型）
- `KnowledgePackage`：知识点完整数据包（原文+结构+关系+笔记+版本）
- `NaturalKnowledgeNote`：自然笔记（contentMarkdown、引用标记、术语/符号更新、警告）
- `CourseGenerationMemory`：课程级记忆（术语表、符号表、已生成摘要）
- `GlobalKnowledgeAnchor` / `CourseKnowledgeOccurrence`：跨PPT锚点数据基础
